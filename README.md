# 深度调研 · Deep Research

一套面向决策的中文调研 Skill。输入研究主题和希望解决的问题，由智能体选择必要方法、查证资料、检验反例，输出有适用条件的结论和下一步建议。

**一个研究入口 + 四种研究方法 + 十二个专项 + 六种成果结构。** 简单问题给短结论，重要决策再展开；无需每次手动拼接模块。

[下载完整 ZIP](https://github.com/ddawoo/deep-research/archive/refs/heads/main.zip) · [技能正文](SKILL.md) · [跨平台通用提示词](prompts/universal-research-prompt.md)

## 能研究什么

| 方法 | 研究方向 |
| --- | --- |
| 产品与技术 | 软件产品与功能、竞品、技术与开源项目 |
| 商业与市场 | 市场需求与商业机会、行业、财务与投资 |
| 研究与认知 | 主题观点、政策法律、历史案例、学习体系 |
| 内容与增长 | 自媒体与内容创作、营销与运营增长 |

专项可以组合，例如产品立项以用户任务为主，按需补充市场、竞品、技术与合规研究。成果可采用综合、产品、竞品、商业机会、观点或技术选型结构。

## 安装为 Skill

1. 下载 ZIP 并解压，找到包含 `SKILL.md` 的文件夹，将其命名为 `deep-research`。
2. 把该文件夹放进所用智能体的技能目录，保留 `references/` 和 `agents/`。Codex 的默认用户技能目录为 `~/.codex/skills/`，最终路径应为 `~/.codex/skills/deep-research/SKILL.md`。
3. 在工具加载该技能后，明确调用 `$deep-research`，并提供研究任务。其他工具按各自技能导入方式操作。

```text
使用 $deep-research。
研究主题：在线学习产品是否值得在第一版加入 AI 笔记。
研究目标：判断用户价值、开发优先级和最小功能范围。
约束：先做低成本验证，再决定是否投入开发。
```

也可以这样提问：

```text
使用 $deep-research，验证“AI 工具越多，工作效率越低”这个观点。
先研究它在什么条件下成立，给出支持证据、反例和独立判断。
```

```text
使用 $deep-research，研究面向小团队的自动报告服务是否存在真实需求。
重点判断谁愿意付费，以及用什么最小实验验证。
```

## 在 ChatGPT、Gemini 或普通聊天中使用

打开 [跨平台通用提示词](prompts/universal-research-prompt.md)，复制完整正文或将文件上传，再补充研究主题和目标。该文件已包含所有研究方法、十二个专项和六种成果结构，不依赖外部参考文件，也不依赖本项目之前的聊天记录。

具体平台能否导入原生 Skill、能否与某个研究功能搭配使用，由该平台当前能力和账号决定。本项目提供可移植的研究规则；检索、浏览和数据读取由所用智能体提供。

## 研究质量规则

- 用能证明当前主张的证据，不把官方介绍、用户兴趣或流行度当作所有问题的答案。
- 重要结论就近引用，检查原始来源、时效、口径与来源独立性。
- 区分已核实事实、分析推断、未验证假设，以及建议开展的工作。
- 主动处理反面证据，允许得出“先验证”或“暂不推进”。
- 没有进行访谈或实际测试时，明确列为计划；无法联网时说明资料边界。
- 当继续搜索不再改变建议时结束，把关键缺口转成具体验证动作。

## 文件结构

```text
deep-research/
├── SKILL.md                         # 研究入口、证据与判断规则
├── agents/openai.yaml               # 技能展示与调用信息
├── references/
│   ├── methods.md                   # 四种研究方法
│   ├── domains.md                   # 十二个专项
│   └── report-templates.md          # 六种成果结构
├── prompts/
│   └── universal-research-prompt.md # 完整独立的通用提示词
├── README.md
└── LICENSE
```

这些是研究方法与指令，不是内置搜索引擎，也不需要本项目专属的 API Key。实际结果取决于宿主工具的能力、资料可用性和本次证据质量。
